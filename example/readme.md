# doc see [website](https://rbatis.github.io/rbatis.io/#/)

## setup

* 1 It is recommended to clone this project using Intellij Clion/VSCode

* 2 next,you should run command `git clone https://github.com/rbatis/rbatis.git`

* 3 next,you should run command `git pull`

* 4 next,you should run command `cargo update`

## run an example

from the repository root:

```shell
cargo run -p example --bin crud
```

or from the example/ directory:

```shell
cd example
cargo run --bin crud
```

sqlite examples use `sqlite://target/sqlite.db` (the db file is created under `target/`).
`build.rs` pre-creates the `activity` table in both possible locations, so every example has
a table to read/write no matter from which directory it is run.

### These examples provide a comprehensive overview of rbatis's features and functionalities.

* crud.rs: Demonstrates basic CRUD (Create, Read, Update, Delete) operations generated by `crud!`.
* crud_insert.rs: insert and insert_batch with a batch size.
* crud_select.rs: select_by_map, a map value `["1","2","3"]` converts to `in (...)`.
* crud_update.rs: update_by_map.
* crud_update_skip.rs: update_by_map with the `"column"` key to update only selected columns.
* crud_delete.rs: delete_by_map.
* crud_json.rs: Shows storing and querying JSON data (struct/Vec fields as JSON columns).
* macro_proc_pysql.rs: Demonstrates the usage of `#[py_sql]` and the `pysql!` wrapper.
* macro_proc_htmlsql.rs: Shows the usage of `#[html_sql]` (inline Mybatis-3 style dynamic SQL).
* macro_proc_htmlsql_struct.rs: `#[rbatis::html_sql("example.html")]` on an `impl` block; each method maps to the `<select>/<update id="...">` of the html file, `Page<T>` pagination is detected from the return type.
* macro_proc_rawsql.rs: Shows how to use raw SQL statements (`#[sql("... ?")]`) in rbatis.
* raw_sql.rs: rb.exec / rb.exec_decode without any macro.
* table_extend.rs: Demonstrates a struct inheriting members from another struct (`#[serde(flatten)]`).
* table_util.rs: `table!`, `table_field_map!`, `table_field_btree!`, `table_field_vec!` helpers (no database needed).
* plugin_table_sync: Illustrates automatically synchronizing struct definitions to table structures (`RBatis::sync`).
* transaction: Shows how to use transactions (`acquire_begin`, `auto_commit` commit/rollback on drop).
* plugin_intercept: Demonstrates the usage of interceptors in rbatis (count the running time of every statement).
* plugin_intercept_log: Control the level of the default LogInterceptor.
* plugin_intercept_returning_id: Add `returning id` to insert statements through an interceptor (needs a local postgres, see docker below).
* plugin_intercept_read_write_router: Read write separation DataBase through an interceptor.
* plugin_intercept_dynamic_table_name: Rewrite the table name inside the SQL through an interceptor (sharding-like).
* pool_config: Configure the default connection pool (FastPool) parameters.
* pool_custom: Shows how to customize connection pool with a third party pool (deadpool).

### docker

* mysql
```
docker run -d --name mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 mysql
```

* postgres
```
docker run --name postgres  -e POSTGRES_PASSWORD=123456 -p 5432:5432 -d postgres
```

* mssql
```
docker run -e "ACCEPT_EULA=Y" -e "SA_PASSWORD=TestPass!123456" -p 1433:1433 --name sqlservercontainer -d mcr.microsoft.com/mssql/server:2022-latest
```
